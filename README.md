# vpn

Конфигурация личного VPN-сервера и клиентские профили к нему.

> **Репозиторий публичный.** Сюда не попадает ничего, что даёт доступ к серверу:
> ни адрес, ни пароли, ни ключи. Всё, что забирается с сервера, проходит через
> `.github/scripts/sanitize.py`, который заменяет адреса, имена хостов, пароли и
> ключи на маркеры вида `<ip-1>`, `<domain-1>`, `<redacted>`.

## Что где

| Путь                   | Что это                                                        |
|------------------------|----------------------------------------------------------------|
| `karing/`              | профиль sing-box для Karing: hysteria2 + российский трафик direct |
| `server/`              | обезличенный слепок конфигурации сервера (создаёт workflow)     |
| `.github/workflows/`   | `vpn-inventory` — забирает слепок с сервера по SSH              |
| `.github/scripts/`     | сбор, нормализация SSH-ключа, обезличивание                     |

Начать стоит с [`karing/README.md`](karing/README.md) — там инструкция по
клиентскому конфигу.

## Секреты репозитория

| Секрет                | Обязателен | Что в нём                                    |
|-----------------------|------------|----------------------------------------------|
| `VPN_HOST`            | да         | `user@host`, `host` или `host:port`          |
| `VPN_SSH_KEY`         | да         | приватный SSH-ключ целиком, включая строку `-----END ...-----` |
| `VPN_SSH_PASSPHRASE`  | если ключ зашифрован | парольная фраза ключа               |
| `VPN_KNOWN_HOSTS`     | да         | вывод `ssh-keyscan <host>`                   |

## Запуск сбора

Workflow `vpn-inventory` срабатывает при изменении своих скриптов и по кнопке
**Run workflow**. Он ходит на сервер только на чтение: собирает конфиги, вывод
`docker ps`, юниты systemd, логи и список открытых портов, обезличивает всё это
и коммитит в `server/`.
